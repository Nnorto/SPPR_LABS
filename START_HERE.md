# Три лабораторные: запуск на MacBook

В комплекте находятся исходники, автотесты, отчёты и разбор для защиты. Сначала запусти готовые демонстрации, затем прочитай `DEFENSE_GUIDE.md` и повтори запросы самостоятельно.

## Что выбрано

- **Лабораторная №1, Wolfram Alpha API:** Python, 10 обязательных и 5 дополнительных запросов. В комплекте есть полностью автономный тестовый режим, но он не заменяет настоящую интеграцию.
- **Лабораторная №2, погода:** все три самостоятельных задания и проект №4, «Подсчёт нарушений».
- **Лабораторная №3, нечёткий анализ погоды:** Python, OpenWeatherMap, исторические данные и алгоритм Мамдани для Казани, Москвы и Санкт-Петербурга. Основание: вновь приложенный DOCX «Лабораторная 3 Погода Fuzzy ЯП на выбор».
- **Исходный архив Pogoda-4.zip:** готовое решение реализовано самостоятельно; исторические данные загружены из NASA POWER. Второй адаптер позволяет использовать Open-Meteo.

## Важное до сдачи

Первая и вторая работы проверены; для первой выполнены и настоящие запросы. Папка `Lab_1_Wolfram/verified_live` содержит 15 успешных ответов API от 7 октября 2026 года, полные JSON, извлечённые данные, отчёт и журнал.

В третьей работе проверены расчёты на реальной истории и 32 локальных теста, но предоставленный ключ OpenWeatherMap при проверке вернул HTTP 401. Поэтому живой запуск третьей работы пока не подтверждён: его нужно выполнить после исправления доступа. `results_historical` не является текущей погодой.

На собственном Mac перед защитой повтори обычный запуск без `--demo`, чтобы убедиться в доступе к API именно с твоего компьютера. Не выдавай папку `example_demo` за ответы Wolfram: она явно помечена как учебная.

ФИО, группа, вуз, дисциплина и преподаватель в титульных листах оставлены для заполнения. Факты о погоде и нарушениях во второй работе учебные; история третьей работы получена из реального погодного продукта и явно обозначена своим периодом.

## Установка программ

### Проверить, что уже установлено

Открой приложение «Терминал» через Spotlight. Выполни команды отдельно:

```bash
python3 --version
swipl --version
```

Для всего комплекта рекомендуется Python 3.11 или новее. Первая работа использует стандартную библиотеку, а для третьей необходима установка зависимостей в виртуальное окружение.

### Установить Python

Если подходящего Python нет, установи актуальную поддерживаемую версию через официальный установщик `python.org`; установщики macOS поддерживают Apple Silicon и Intel. После установки открой `Install Certificates.command` в папке установленного Python, как указано в [официальной инструкции Python](https://docs.python.org/3/using/mac.html).

Не удаляй и не заменяй системный `/usr/bin/python3`. Официальная документация предупреждает, что он управляется Apple и может использоваться системными инструментами: [Python на macOS](https://docs.python.org/3/using/mac.html).

### Установить SWI-Prolog

Если Homebrew уже есть, выполни:

```bash
brew install swi-prolog
swipl --version
```

Команда установки приведена в [официальной инструкции SWI-Prolog для macOS](https://www.swi-prolog.org/build/macos.html). Для наших консольных программ графические библиотеки и XQuartz отдельно не нужны.

Если команда `brew` не найдена, установи Homebrew по инструкции на [brew.sh](https://brew.sh/), затем выполни показанные установщиком завершающие действия и открой новое окно Терминала. Не используй случайные инструкции с отключением защиты macOS.

Альтернатива без установки Prolog: [SWISH](https://swish.swi-prolog.org/), который также указан в приложенном PDF. В новый Program вставь содержимое `weather.pl` или `violations.pl`, а запрос вводи в отдельном поле; `demo.pl` с локальными `ensure_loaded` туда переносить не нужно.

## Распаковать и открыть комплект

Распакуй `Three_Labs_Mac.zip`. Предполагается, что папка `labs_mac` находится в «Загрузках»:

```bash
cd ~/Downloads/labs_mac
```

Если сохранил в другое место, набери в Терминале `cd ` с пробелом, перетащи папку `labs_mac` в окно и нажми Enter. Ниже команды запуска из корня комплекта, если не указано другое.

Создай окружение и установи зависимости третьей работы:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r Lab_3_FuzzyWeather/requirements.txt
```

После открытия нового окна Терминала снова перейди в `labs_mac` и выполни `source .venv/bin/activate`. Саму установку зависимостей повторять каждый раз не требуется.

## Быстрый показ всех трёх работ

### Первая работа: проверить программу без ключа

```bash
python3 Lab_1_Wolfram/main.py --demo
```

Программа обработает 15 синтетических примеров: 7 с контрольными вычислениями и 8 с моделируемым отсутствием результата. В этом режиме обращения к Wolfram нет; это проверка архитектуры, парсинга и сохранения файлов.

Путь к новой папке результатов появится в последней строке. В ней находятся:

- **`raw/`:** отдельный JSON для полного ответа каждого запроса; в демо это синтетические фикстуры.
- **`extracted/`:** отдельно извлечённые текстовые блоки и статус каждого запроса.
- **`summary.json`:** сводный список всех запросов и результатов.
- **`report.md`:** читаемый отчёт.
- **`run.log`:** журнал выполнения.

### Первая работа: настоящие запросы

Ты уже создал приложение и получил AppID: для локальной настройки нужен именно этот идентификатор, а не Name или Description. Наличие AppID обязательно для запросов Full Results API; порядок описан в [документации Wolfram](https://products.wolframalpha.com/api/documentation).

Если потребуется новый ключ, открой портал из официальной документации и выбери «Get an AppID». Действующие условия доступа и лимиты проверяй в своём аккаунте; цифры со старых скриншотов методички не гарантируют текущих условий.

В корне комплекта выполни:

```bash
python3 Lab_1_Wolfram/setup_config.py
```

Вставь ключ в скрытый ввод и нажми Enter. Скрипт создаст локальный `config.json`; на macOS права файла устанавливаются только для владельца.

Затем запусти:

```bash
python3 Lab_1_Wolfram/main.py
```

Должен появиться режим `LIVE / WOLFRAM API`. Успешный запуск сохраняется в новой папке `Lab_1_Wolfram/output/live_...`; исходная папка `example_demo` не перезаписывается.

Для просмотра уже полученных настоящих результатов без повторных обращений к API:

```bash
python3 Lab_1_Wolfram/show_saved_results.py
```

Этот скрипт читает `verified_live`, а не выполняет новый запрос. Динамические значения в сохранённых ответах относятся к моменту проверки, а не к моменту их повторного просмотра.

Некоторые формулировки API может не распознать, даже если интернет и ключ исправны. Программа не подставляет выдуманный ответ: сохраняет исходную реакцию и статус `no_result`, `api_error`, `request_error` или `no_text`.

Если есть неуспешные запросы, пакет продолжится, а код завершения будет `1`. Изучи `raw`, исправь проблему доступа или уточни формулировку отдельно; исходные 10 запросов методички в `queries.py` сохранены дословно.

Никому не отправляй `config.json`, не вставляй AppID в отчёт и не показывай его на скриншотах. `.gitignore` исключает файл из обычного добавления в Git, но не защищает от ручного включения в ZIP.

### Вторая работа: погода и нарушения

```bash
swipl -q -s Lab_2_Weather/demo.pl -g demo -t halt
```

Будут показаны советы для четырёх городов, проверки граничных скоростей ветра, примеры активности и число нарушений для трёх автомобилей. Для интерактивной работы:

```bash
swipl -q -s Lab_2_Weather/weather.pl
```

Теперь видишь приглашение `?-`. Вводи только текст запроса, без копирования самого `?-`:

```prolog
advice_for('Екатеринбург', A).
wind_advice(10, A).
wind_advice(10.1, A).
activity_advice(21, солнечно, A).
show_all_advices.
halt.
```

Точка в конце каждого запроса обязательна. `halt.` завершает Prolog и возвращает в Терминал.

### Третья работа: нечёткая погодная система

```bash
python Lab_3_FuzzyWeather/main.py --historical-demo
```

Программа рассчитает сезонные статистики и вывод Мамдани на последней реальной записи истории. Это 31 декабря 2025 года, а не текущая погода; исходные данные и готовый запуск уже включены в архив.

Для текущих условий нужен отдельный ключ OpenWeatherMap:

```bash
python Lab_3_FuzzyWeather/setup_config.py
python Lab_3_FuzzyWeather/main.py --refresh-current
```

Если API возвращает 401, текущая погода не получена. Не выдавай исторический пример за успешную сетевую интеграцию; подробности запуска, единиц и источников находятся в `Lab_3_FuzzyWeather/README.md`.

После успешного запроса `python Lab_3_FuzzyWeather/main.py` повторно обработает сохранённые ответы без сети. Время наблюдений выводится явно; старый кэш помечается предупреждением.

Из корня комплекта:

```bash
bash check_all.sh
```

Проверка включает 28 тестов первой работы, 31 тест второй и 32 теста третьей. Всего 91 тест; эти тесты не подтверждают доступ к внешним API.

Фактическая локальная проверка проведена в Linux с Python 3.14.3 и SWI-Prolog 9.2.9. macOS на твоём MacBook удалённо не проверялась; команды и код подготовлены для запуска на ней.

## Что показать преподавателю

- **Первая работа:** `queries.py`, `configuration.py`, `client.py`, `processing.py`; затем настоящий запуск, один полный JSON и соответствующий извлечённый результат. Покажи, что `output=json` относится к формату ответа, а `format=plaintext` к содержимому блоков; это разные параметры [Wolfram Full Results API](https://products.wolframalpha.com/api/documentation).
- **Вторая работа:** `weather.pl`, три добавленных возможности и `violations.pl`. Сравни ветер 10 и 10.1 м/с, затем покажи известную машину без нарушений.
- **Третья работа:** `architecture.drawio`, сезонную таблицу, `fuzzy_model.py`, функции принадлежности и трассировку правил в `analysis.json`. Различай текущую погоду, кэш и исторический пример.

В каждой папке есть `REPORT.md` и редактируемый `REPORT.docx`. В третьей работе полный многофайловый листинг вынесен в `SOURCE_CODE.md`, а основная модель приведена в отчёте; автотесты находятся рядом с исходниками.

## Если возникла ошибка

- **`command not found: swipl`:** установи SWI-Prolog и перезапусти Терминал; проверь `command -v swipl`.
- **`can't open file` / `source_sink ... does not exist`:** неверная папка. Повтори `cd` в корень `labs_mac`, не переименовывай внутренние папки.
- **`Нет config.json`:** вызови `setup_config.py`. Для проверки без ключа используй `--demo`.
- **Нет ключа OpenWeatherMap:** для третьей работы без ключа используется `--historical-demo`, а не `--demo`.
- **`ModuleNotFoundError` в третьей работе:** активируй `.venv` и установи её `requirements.txt`.
- **HTTP 401/403 или API `Invalid appid`:** проверь AppID и доступ к Full Results API в аккаунте. Не отключай проверку HTTPS.
- **Ошибка сертификата после установки Python:** выполни `Install Certificates.command`, как описывает [Python](https://docs.python.org/3/using/mac.html).
- **`no_result`:** сервер не вернул успешный результат для формулировки. Это не то же самое, что обрыв сети.
- **`Unknown procedure: weather/3`:** в расширенной работе у погоды четыре аргумента, поэтому нужен `weather/4`.
- **`Syntax error` в Prolog:** проверь точку, запятые и прямые одинарные кавычки. Не используй типографские `‘ ’` в коде.
- **Русский текст выглядит как `\u041C...`:** в Prolog выполни `set_stream(user_output, encoding(utf8)).`; готовые `demo.pl` делают это сами.
