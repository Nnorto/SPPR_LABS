# Лабораторная №3: погодная система нечёткого вывода

Это работа по новому файлу «Лабораторная 3 Погода Fuzzy ЯП на выбор». Здесь нет покраски и семейной базы: используются погодные API, сезонные статистики и настоящий вывод Мамдани.

## Что реализовано

- **Текущая погода:** OpenWeatherMap для Казани, Москвы и Санкт-Петербурга.
- **История:** два адаптера, Open-Meteo / ERA5 и NASA POWER / MERRA-2. В комплект включены реальные данные NASA за 2021–2025, потому что Open-Meteo вернул исчерпание дневного лимита.
- **Статистика:** 12 комбинаций город–сезон, средние, выборочные стандартные отклонения, минимумы и максимумы.
- **Мамдани:** сезонные температурные термы, влажность, ветер, 7 общих правил и одно правило города; дефаззификация центром тяжести.
- **Результаты:** CSV, JSON с трассировкой, Markdown и PNG-графики.
- **Документация:** отчёт, гайд защиты, полный код с комментариями и редактируемая схема draw.io.

Исторические значения представляют реанализ на сетке, а не прямые наблюдения выбранной городской станции. Кэш текущей погоды и исторический пример никогда не подменяют друг друга.

## Установка на Mac

Из распакованной папки `labs_mac`:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r Lab_3_FuzzyWeather/requirements.txt
cd Lab_3_FuzzyWeather
```

Рекомендуется Python 3.11 или новее. Установка зависимостей требует интернета; дальнейший анализ включённой истории работает без сети.

## Первый запуск без API-ключа

```bash
python main.py --historical-demo
```

Этот режим использует настоящие последние записи исторического ряда, а не придуманную погоду. Он явно называется `historical-demo`: это данные 31 декабря 2025 года, НЕ текущие условия.

Файлы уже выполненного исторического запуска лежат в `results_historical`. Повторный запуск создаёт новую подпапку `output` и не перезаписывает отчётный пример.

## Настоящая текущая погода

Создай конфигурацию локально и вставь ключ в скрытый ввод:

```bash
python setup_config.py
python main.py --refresh-current
```

Нужен ключ именно OpenWeatherMap из личного кабинета API keys. При HTTP 401 проверь ключ и активацию: новый ключ может активироваться до двух часов после регистрации, согласно [FAQ OpenWeatherMap](https://openweathermap.org/faq).

При неуспешном запросе программа возвращает ошибку, а не подставляет исторические данные. После успешной загрузки можно повторить анализ сохранённых ответов без сети:

```bash
python main.py
```

Проверяй `observed_at_utc`: это время данных API. Слово «текущая» относится к моменту получения, а не к дате повторного чтения кэша.

## Повторная загрузка истории

История уже приложена, загружать её каждый раз не нужно. Для NASA используются отдельные запросы по годам, включая 31 декабря 2020 года для правильного перехода UTC → московское время:

```bash
python main.py --download-history nasa --historical-demo
```

Чтобы получить именно Open-Meteo в отдельную папку, не смешивая два реанализа:

```bash
python main.py --data data_openmeteo --download-history openmeteo --historical-demo
```

Если сервис сообщил дневной лимит, дождись его обновления или используй уже включённую независимую историю NASA. Не запускай повторные запросы в цикле при исчерпанной квоте.

## Файлы и их назначение

- **`data/history/nasa_raw/`:** оригинальные JSON-ответы NASA и метаданные запросов.
- **`data/history/kazan.json`, `moscow.json`, `spb.json`:** нормализованные производные файлы с явной пометкой происхождения.
- **`data/current/`:** настоящие ответы OpenWeatherMap, только после успешного доступа.
- **`seasonal_norms.csv`:** полная таблица сезонных статистик.
- **`comparison.csv`:** входные показатели, отклонения и итоговый индекс.
- **`analysis.json`:** степени принадлежности, активации правил и рекомендации.
- **`data_quality.json`:** число записей, пропуски, исключения и покрытие.
- **`figures/`:** функции принадлежности, сезонные профили, временные ряды и индекс комфорта.
- **`architecture.drawio`:** редактируемая схема; открыть в draw.io / diagrams.net через импорт файла.
- **`REPORT.docx`:** редактируемый отчёт; заполнить титульный лист.

## Проверка

```bash
python -m unittest -v
```

Тесты проверяют обработку API, безопасность сообщений об ошибках, единицы, часовые пояса, пропуски, формулы статистики, граничные значения и независимый расчёт центра тяжести. Тесты не подтверждают правильность текущего API-ключа.

## Важные ограничения

Пять лет дают учебную базовую статистику, но не официальную многолетнюю климатическую норму. Порог \(|z|>2\) выбран для демонстрации; он не задаёт вероятность опасного явления.

Комфорт 0–100 является условным выходом авторской базы правил. Он не является вероятностью, медицинской оценкой или официальным предупреждением; защитные рекомендации показываются отдельно.

## Документация используемых сервисов

Current Weather API и его поля описаны в [OpenWeatherMap](https://openweathermap.org/current). Альтернативные источники истории описаны в [Open-Meteo Historical Weather API](https://open-meteo.com/en/docs/historical-weather-api) и [NASA POWER Hourly API](https://power.larc.nasa.gov/docs/services/api/temporal/hourly/).

Принципы использования `Antecedent`, `Consequent`, `Rule`, `ControlSystem` и `ControlSystemSimulation` показаны в [официальном примере scikit-fuzzy](https://scikit-fuzzy.readthedocs.io/en/latest/auto_examples/plot_tipping_problem_newapi.html). В нашем решении эти компоненты формируют вычисляемую модель, а не только иллюстрации.
